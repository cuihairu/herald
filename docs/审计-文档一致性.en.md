# Document-to-Source Consistency Audit (2026-10-08)

A whole-repository documentation cross-check audit executed per the *Document-to-Source Consistency Audit Specification*: enumerate the documentation surfaces -> extract verifiable technical claims and cross-check each one against the source for evidence (each entry gives file:line; for an empty grep, verify the path first before drawing a negative conclusion) -> record the three categories of difference in the table -> fix the docs with the source as truth (reverse code changes forbidden).

- Three categories of difference: **A** the docs run ahead of the code (ghost features) / **B** the code runs ahead of the docs (missing) / **C** the description does not match (wording, defaults, key names, behavior).
- Severity: **P0** configuring per the docs would produce an incident / **P1** key claims are distorted, misleading integration or review / **P2** wording drift, stale checklist.
- Remediation principles: the source is the only truth; things that run ahead get deleted or annotated, things that are missing get filled in, things that do not match get their wording corrected. After the audit, the docs become the review baseline.
